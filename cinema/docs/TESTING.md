# Чек-лист выпуска и результаты QA

## Автоматические проверки

`npm test`: граф двух сценариев, достижимость узлов, обе концовки, альтернативные маршруты, одна мутация, возврат, восстановление прошлых состояний, закрытый архив, локальный JSON, повреждённые сохранения и локализации.

`npm run check`: синтаксические проверки JS и тесты Node.js.

## Browser QA

Установленный в среде Chromium блокирует навигацию на `localhost` и произвольные домены (`ERR_BLOCKED_BY_ADMINISTRATOR`). Для проверки визуальной части создан вспомогательный тестовый self-contained HTML (`tools/make_browser_preview.py`) с **теми же сценариями и логикой**, но изображения и код встроены как data URL. Скриншоты получены через Playwright `page.set_content`, а не через опубликованный сайт. Это подтверждает браузерное поведение при такой упаковке, **не является production/e2e тестом реального домена**.

Проверенные сценарии:
- desktop 1440×900: вступление, переходы, меню архива, настройка режима;
- mobile 390×844: вступление, выбор маршрута, отсутствие горизонтального переполнения;
- 3-сценный прототип: разные финальные состояния;
- проверки управления с клавиатуры и повторного открытия архива (автоматические и ручные).

## Перед публичным релизом обязательно

- Проверить по обычному `http://localhost:8080` на собственной машине, а затем по HTTPS на тестовом домене.
- Проверить слабый Android и iPhone Safari; тексты RU/EN/ZH, скролл и кнопки.
- Заменить производственные ключевые кадры на реальные чистые 16:9 и 9:16.
- Провести WCAG-проверку screen-reader и цветового контраста.
- Уточнить настоящий адрес и доступность рекламной платформы в `story/site-config.mjs`.
- Не считать художественные действия регистрациями и продажами.
