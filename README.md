# PROTOCOL ZERO v3.4.0 — Cinema + Inheritance

Integrated source: 15-scene interactive cinema in `/cinema/`, SQLite-backed advertising lineage, explicit opt-in public mutations. Development build; no real advertising partners, payments or sales. Requires Node.js >=22.13.0. Run `npm test`, `npm start`, then open http://127.0.0.1:8787/cinema/.

---

# PROTOCOL ZERO — CINEMA × НАСЛЕДНИКИ / v3.4.0

**Исходники объединённой версии:** кинематографическое веб-кино на 15 сцен (`/cinema/`) и рекламная платформа «Наследники» (`/`) работают с одной серверной базой SQLite. Просмотр кино доступен без регистрации. Создание *публичной* наследуемой мутации требует явного подтверждения в диалоге, остальные решения фильма остаются локальными.

**GitHub:** исходный код, готовые оптимизированные WEBP-кадры и образцы конфигурации можно безопасно публиковать. Исходные большие референсные изображения для опционального повторного рендера `cinema/tools/make_assets.py` отсутствуют в облегчённом репозитории; runtime их не использует. Не публикуйте содержимое `data/`, реальные `.env`, `.session-secret`, внутренние клиентские брифы и секреты партнёров.

## Быстрый запуск

Требуется Node.js >=22.13.0; зависимости npm не нужны.

```sh
npm start           # http://127.0.0.1:8787 (кино: /cinema/)
npm run demo        # портал + ОТДЕЛЬНАЯ локальная тестовая рекламная площадка на :8790
npm test            # полная проверка HTTP API и логики
npm run smoke       # проверка работающего HTTP сервера
```

На Windows доступны `START_WINDOWS.cmd` и `START_DEMO_WINDOWS.cmd`. Для публикации смотрите `docs/DEPLOY.md`. Перед миграцией всегда сохраняйте `data/` и секреты отдельно. Для первого запуска секрет сессии генерируется локально, для production задавайте `SESSION_SECRET` в защищённых переменных окружения.

**Новая интеграция v3.4.0:** `/api/cinema/candidates` возвращает только пригодные для наследования публичные кампании; `POST /api/cinema/publish` сохраняет потомка после согласия, а `/api/cinema/consequences/:id` показывает потомков. Тестирование двух независимых сессий: `tests/cinema-integration.test.js`. Установка отдельной регистрации для просмотра не требуется.

**Текущий статус:** локальная проверяемая сборка; семь внешних сайтов не подключены, live-продажи и платежи отсутствуют. Демонстрационные действия **не являются** доказанной эффективностью рекламы.

## Запуск на Windows за один шаг

1. Распакуйте весь ZIP с исходниками, не запускайте программы внутри архива.
2. Установите **Node.js 22.13+** (проверено на 22.16).
3. Запустите **`START_DEMO_WINDOWS.cmd`** двойным щелчком.
4. Откройте **http://127.0.0.1:8787**.
5. Выберите демобриф, измените **одну** деталь, сохраните новую публичную ветвь.
6. Нажмите **«Передать в продукт»**, выберите тестовую рекламную мастерскую, прочитайте список передаваемых данных и подтвердите.
7. Нажмите «Открыть демонстрационную рекламную мастерскую» (партнёрское приложение работает на `http://127.0.0.1:8790`).
8. На странице второго приложения нажмите **«Сохранить демонстрационный рекламный макет»**.
9. Вернитесь на **http://127.0.0.1:8787/bridge** — статус будет **«Демо подтверждено»**, а настоящие рекламные результаты останутся **0**, как и должно быть.

Для macOS/Linux: `./START_DEMO_MAC_LINUX.sh`. Универсальная команда: **`npm run demo`**.

Если нужен **только портал без второго сервера**: `START_WINDOWS.cmd` или `npm start`. Тогда подключений по умолчанию не будет, но мутации, ветви, родословная, личная мастерская, карточки и экспорт продолжат работать. Устанавливать npm-пакеты (`npm install`) не требуется.

**База данных:** `data/protocol-zero.sqlite` хранит ветви, приглашения, приватные черновики, историю передач. Демо-партнёр хранит собственные результаты в `data/demo-partner.sqlite`. Файлы SQLite и реальные пользовательские данные **не входят в релизный ZIP**.

## WAVE 11–15 — новая версия v2.8.0

Добавлены **пять рабочих волн** поверх v2.3.0 с сохранением прежней родословной, отзывов, рекламных планов и коммерческих заявок.

1. **WAVE 11 — Campaign Control.** Автор брифа может поставить одобренную кампанию на паузу и затем снова открыть. При паузе заблокированы новые мутации и приглашения, но история читается. Все изменения состояния заносятся в журнал. Для утерянной анонимной сессии предусмотрена отдельная **локальная** операторская команда восстановления.
2. **WAVE 12 — Creative Evidence Packs.** Закрытые пакеты от 1 до 8 публичных версий. Снимок креативов в JSON и SHA-256 фиксируются неизменяемо. Пакет доступен только создателю брифа; скрытые модерацией ветви не раскрываются даже через ранее сохранённый пакет. Хеш — контроль целостности, **не цифровая подпись внешнего независимого аудитора**.
3. **WAVE 13 — Experiment Closure.** Владелец завершает A/B-эксперимент с обязательной причиной и сохранением снимка проверки качества данных. После закрытия API больше не принимает назначения, показы и цели **даже с правильной подписью** партнёра. Автоматических победителей и выдуманной статистической значимости нет.
4. **WAVE 14 — Pilot Milestones.** Оператор после стадии согласия на пилот добавляет этапы выполнения; заказчик проверяет представленные этапы, отмечает ознакомление или запрашивает исправления. История статусов сохраняется. Это **не подтверждение оплаты, договора или юридической приёмки**.
5. **WAVE 15 — Business Control Centre.** Один адаптивный кабинет для владельца одобренного брифа: контроль кампании, фактическая активность, сохранённые пакеты, закрытые A/B-планы, коммерческие пилоты и этапы. Экспорт по уже действующим API; **выручка, ROMI и гарантированная эффективность не рассчитываются**.

**Как открыть:** запустите приложение → `/submit` («Для бизнеса») → отправьте собственный бриф → оператор проверяет и одобряет его → в списке «Мои заявки» выберите **«Центр бизнеса»**. Прямая ссылка: `/command/BRF-ID` при наличии доступа автора в данном браузере. С чужой сессии доступ закрыт.

**Операторские команды:**

```bash
npm run ops -- campaign-pause BRF-ID "Нужно временно перепроверить рекламные формулировки"
npm run ops -- campaign-resume BRF-ID "Формулировки подтверждены внутренней командой"
npm run ops -- milestones PIL-ID
npm run ops -- milestone-add PIL-ID "Подготовка рекламных версий" "Описаны три независимые идеи и получено согласование состава"
npm run ops -- milestone-submit PIL-ID MS-ID "Результаты этапа переданы заказчику в его закрытом кабинете"
```

Команды с `PIL-ID` доступны после стадии **accepted** (согласие клиента на рассмотрение коммерческого предложения, без платежа). Проверьте ID и тексты перед запуском; операторская консоль не доступна публично через HTTP.

**Перед обновлением:** остановите прежний сервер; сохраните всю папку `data/` вместе с `.session-secret`, а также свои env-переменные и реестр платформ. Распакуйте ZIP в **новый** каталог, перенесите данные и протестируйте миграцию на отдельной копии SQLite. Она добавляет только новые таблицы. Не обновляйте работающую базу на лету. Подробности: [docs/WAVES_v2.8.0.md](docs/WAVES_v2.8.0.md), [docs/RELEASE_NOTES_v2.8.0.md](docs/RELEASE_NOTES_v2.8.0.md), [docs/API_v2.8.0.md](docs/API_v2.8.0.md).

**Релизная проверка:** `npm run check && npm test && npm run smoke && npm run verify:release` — **66/66 тестов**, smoke и проверка SHA-256. Метрики тестов не являются показателями реальных клиентов. Сеть Chromium на локальном адресе ограничена средой: интерактивные браузерные проверки выполнялись через изолированный мост к настоящим HTTP-ответам API, не на публичном production-сайте.

## Новое в v1.3 — заявки компаний и настоящий B2B-контур

- Страница **«Для бизнеса»** (`/submit`) с доступной формой, ограничениями текста и обязательным подтверждением прав на материалы.
- Приватные заявки в SQLite: **до одобрения ничего не публикуется**. Необязательный email доступен оператору только при отдельном согласии, никакой рассылки нет.
- Операторский CLI `npm run ops -- briefs`, `brief-view`, `brief-approve`, `brief-reject`, `brief-unpublish`, `brief-republish`. Никакой веб-админки с открытым доступом.
- При одобрении создаётся **новая публичная кампания**, а не изменение трёх исходных демобрифов; игроки могут продолжать её по прежним правилам.
- Заявитель видит свои публичные продолжения в разделе **«Результаты людей»** и может скачать до 500 вариантов CSV (без чужих приватных черновиков).
- Появился **серверный Node.js SDK** `sdk/node-partner.js` для интеграции существующих рекламных сайтов; отдельная демоплатформа уже использует его.
- Скрытие проблемной опубликованной кампании блокирует её корень, всех потомков, карточки и незавершённые передачи в продукт.

Простой сценарий проверки: открыть `/submit` → отправить бриф → `npm run ops -- briefs` → `npm run ops -- brief-view ID` → ручная проверка → `npm run ops -- brief-approve ID "Причина проверки и публикации" --manual-review` → обновить главную → создать мутацию новой кампании из **другого браузера** → вернуться автором заявки в «Для бизнеса» → «Результаты людей» → CSV.

Прочитайте [docs/BUSINESS_INTAKE.md](docs/BUSINESS_INTAKE.md) и [docs/NODE_PARTNER_SDK.md](docs/NODE_PARTNER_SDK.md) перед эксплуатацией реальных данных. На публичный EU/международный запуск **не готовы** документы оператора, юридическая проверка, процессы жалоб и хранения персональных данных.

## Что доступно пользователям

- Три публично помеченных **вымышленных** демобрифа, без фальшивых участников или поколений.
- Неизменяемые публичные ветви: изменение только заголовка, тона или призыва; нельзя менять ген предыдущего человека и нельзя продолжать собственную ветвь.
- Одноразовые приглашения, родословная предков и потомков, общая лента и личный архив текущего анонимного браузера.
- Частная рабочая мастерская автора, экспорт `.txt`, JSON рекламного брифа, PNG/SVG для публикации.
- **Новый Conversion Bridge:** явное согласие на передачу брифа, выбор публичной/частной версии, журнал передач, статус открытия, получения и подтверждения, отзыв.
- **Два сервера:** партнёр запрашивает бриф по HMAC-подписи, записывает свой демо-макет в собственную SQLite и сообщает результат обратно по подписанному callback.
- Отдельный подсчёт sandbox vs live, операторский отчёт и CSV-воронка. Никакое демодействие не превращается в живую конверсию.
- Модерация через CLI, жалобы, лимиты массовых действий, privacy export/delete, резервная копия SQLite.

**Семь будущих продуктов:** реестр разрешает от нуля до семи проверенных интеграций. Пока у нас нет названий, действующих адресов и API реальных сайтов. Никакие их способности не выдуманы.

### Обновление с 1.3.0 (или более ранней версии)

**Остановите старый процесс!** Сделайте резервную копию `data/protocol-zero.sqlite` и секретов сессии (`data/.session-secret` либо `SESSION_SECRET`), затем распакуйте новый ZIP в новую папку. Скопируйте старое содержимое `data/` в эту папку, выполните `npm test` и запустите новую версию. Миграция последовательно добавляет заявки и модерацию v1.3, затем таблицы редакционных оценок и экспериментов, а также `last_seen_at` сессий. Существующие ветви, приглашения и черновики сохраняются. Для действующей базы сначала запустите миграцию на копии. Не копируйте архив поверх работающего процесса. Старые `PLATFORM_NAME`/`PLATFORM_URL` (если заданы) сохраняют обычную ссылку, но новый защищённый Bridge включается отдельно через `PZ_PLATFORMS_FILE`. Детали в `docs/DEPLOY.md`.

## Как подключить первый реальный сайт

Полная инструкция с форматом реестра платформ, безопасным протоколом подписи, JSON-брифом, подтверждением и ограничениями — **[docs/BRIDGE.md](docs/BRIDGE.md)**. Для Node.js backend теперь можно использовать **[sdk/node-partner.js](sdk/node-partner.js)** и [инструкцию](docs/NODE_PARTNER_SDK.md).

1. Подтвердите **настоящие** функции сайта и место, где принимает `pz_handoff`.
2. Добавьте его в приватный JSON реестр по шаблону `config/platforms.example.json`. Используйте настоящий HTTPS-домен, `mode: "live"` и переменную окружения с уникальным HMAC-секретом.
3. В backend сайта реализуйте два server-to-server вызова: `/api/integrations/v2/resolve` для получения брифа и `/api/integrations/v2/confirm` после **фактического сохранения** рекламного объекта.
4. Прогоните тест двумя независимыми браузерами, убедитесь, что live-результат соответствует реальному объекту сайта, а не регистрации/клику.
5. Перед публичным запуском обеспечьте HTTPS, legal/privacy review, защиту от злоупотреблений и резервные копии.

Всё это **подготовлено к интеграции**, но сами сайты пока не подключены. Нельзя считать тестового партнёра реальным рекламодателем.
