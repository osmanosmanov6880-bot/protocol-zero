# Команда и клиентские документы: руководство v3.3.0

## Порядок работы

1. Владелец отправляет бриф в разделе **Для бизнеса**. Оператор после ручной проверки одобряет кампанию.
2. Другой браузер создаёт хотя бы одно публичное продолжение кампании.
3. Владелец переходит **Центр бизнеса → Команда, клиентские материалы и запуск**, создаёт подборку из публичных версий (1–8).
4. В секции «Соберите команду» выбирает роль и срок. Приглашение создаётся только по нажатию кнопки и **показывается один раз**.
5. Другой человек открывает ссылку `/team/join/TOKEN`, принимает её в собственном браузере и попадает на `/team/BRF-ID`.
6. Наблюдатель только читает документы. Рецензент может добавить заметку к выбранной подборке. Никто из них не управляет кампанией и не видит черновики.
7. Владелец выбирает подборку, создаёт «Материалы для клиента» и скачивает HTML или JSON.
8. Для проверки безопасности владелец отзывает членство и убеждается, что гость сразу получает HTTP 403 при обращении к командным данным.

## API

| Действие | Метод | URL |
|---|---|---|
| Создать приглашение | POST | `/api/business-briefs/BRF-ID/team/invites` `{role:'viewer'|'reviewer',days:1|7}` |
| Список участников | GET | `/api/business-briefs/BRF-ID/team` |
| Принять одноразовую ссылку | POST | `/api/team/redeem` `{token}` |
| Отозвать ссылку | POST | `/api/business-briefs/BRF-ID/team/invites/TEAM-ID/revoke` `{}` |
| Закрыть доступ участнику | POST | `/api/business-briefs/BRF-ID/team/members/SESSION-ID/revoke` `{}` |
| Командная мастерская | GET | `/api/team/BRF-ID/workspace` |
| Читать подборку командой | GET | `/api/team/BRF-ID/packs/PACK-ID` |
| Оставить замечание | POST | `/api/team/BRF-ID/notes` `{packId,text}` |
| Выпустить клиентский HTML | POST | `/api/business-briefs/BRF-ID/deliverables` `{packId,label}` |
| Список документов | GET | `/api/business-briefs/BRF-ID/deliverables` |
| Получить документ JSON | GET | `/api/deliverables/DLV-ID` |
| Скачать HTML | GET | `/api/deliverables/DLV-ID/download` |

Для приватных данных нужны cookie того браузера, которому разрешён доступ; административного HTTP API нет. Любые POST-запросы требуют JSON. Используйте HTTPS в публичной сети.

## Ограничения безопасности

- **Вход без логина — компромисс MVP.** Права привязаны к cookie. Потеря cookie означает потерю самостоятельного управления. В полноценном корпоративном продукте потребуются аккаунты, MFA, SSO и восстановление доступа.
- Ссылка — одноразовый ключ доступа. Передайте её адресату по безопасному каналу, не публикуйте и не помещайте в общедоступные журналы.
- Контакты и личные заметки не попадают в командные ответы, но сами творческие варианты могут содержать информацию, введённую пользователями публично.
- Контрольная сумма файла — защита целостности внутри приложения, **не доказательство правообладания, согласия клиента или отсутствия рекламных нарушений**.
- Устранение конфиденциального содержания у стороннего получателя требует самостоятельных процедур у него; отзыв доступа к этому порталу не удаляет уже скачанный файл.
