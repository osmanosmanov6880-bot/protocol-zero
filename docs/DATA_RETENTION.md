# Контроль данных и обслуживание базы v1.8

## Сначала резервная копия

Остановите запись или используйте `npm run backup` в рамках поддерживаемого резервного копирования SQLite. Сохраните базу и `data/.session-secret` либо `SESSION_SECRET` в защищённом месте; не включайте их в исходный ZIP. Проверьте возможность восстановления на независимом экземпляре.

## Операторские команды

```bash
npm run ops -- report
npm run ops -- experiments
npm run ops -- prune
npm run backup
npm run ops -- prune --execute --backup-confirmed
npm run smoke
```

Без `--execute` команда `prune` **не удаляет ничего** и выводит количество подходящих записей. Вариант `--execute` требует `--backup-confirmed`, но система физически не может проверить, что backup действительно сделан: оператор обязан это проверить самостоятельно.

Сроки предварительной политики: игровые/технические события старше 180 дней; неиспользованные просроченные приглашения и передачи с задержкой 30 дней; email отклонённых/отозванных заявок после 90 дней; неиспользованные сеансы без активности после 180 дней. Публичная родословная, действующие приглашения, одобренные кампании и партнёрские подтверждения этим инструментом **не удаляются**. Вручную согласуйте сроки с применимыми правовыми основаниями и договорами до обработки реальных персональных данных.

Анонимные cookie-сессии всё равно могут быть персональными данными, если позволяют выделить устройство/пользователя. Экспорт/удаление собственного сеанса доступны через существующее privacy API. Удаление из портала не удаляет копии брифов, уже полученные внешним партнёром: для такого случая необходим отдельный межсистемный процесс.

## Deployment checklist

- Node.js >=22.13, HTTPS за reverse proxy, отдельный домен, собственные secrets.
- Закрытая папка `data/` с ограниченным доступом ОС; ежедневные backup и тест восстановления.
- `GET /api/ready` должен отвечать HTTP 200; Docker использует этот путь.
- Проверка `npm run check && npm test && npm run smoke && npm run verify:release` для каждой сборки.
- Включить журналы 4xx/5xx, лимиты трафика на уровне reverse proxy и тревоги отказа диска.
- Не подключать непроверенные рекламные сайты, не хранить ключи в frontend, не выдавать sandbox за live.
- Privacy terms, договоры обработки данных, согласия и процессы жалоб — обязательные отдельные задачи перед публичным EU-стартом.

## Дополнение v2.3: комнаты согласования и пилоты

`npm run ops -- commercial-prune` выполняет dry-run и показывает число подходящих к очистке **закрытых/просроченных более 30 дней назад комнат** и **завершённых более 365 дней назад пилотных запросов**. Удаление каскадно затрагивает комментарии, журнал редакционных решений и историю переговоров; публичные ветви/кампании сохраняются. Для выполнения: `npm run backup`, проверить восстановление в отдельной среде, затем `npm run ops -- commercial-prune --execute --backup-confirmed`. Флаг подтверждает **действие оператора**, не доказывает наличия копии автоматически. В `prune` также защищены анонимные сессии, владеющие новой комнатой, пилотом или отзывом.

Если есть применимые юридические обязанности по хранению договора или иных данных, **не запускайте автоматизированную очистку без правового пересмотра**. У нас пока нет договоров и реальных платежей в платформе.
