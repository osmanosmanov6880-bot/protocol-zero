# Обновление с v2.8.0 до v3.3.0

1. Остановите все процессы PROTOCOL ZERO и демонстрационной мастерской.
2. Создайте проверенную SQLite-копию: `npm run backup -- ./backups/pre-v3.3.sqlite`. Отдельно сохраните прежний `data/.session-secret` и секреты в `.env` / менеджере секретов. **Не отправляйте эти файлы в чат и не включайте их в публичные архивы.**
3. Распакуйте v3.3.0 **в новую папку**. Перенесите прежнюю папку `data` либо задайте неизменный путь через `DB_PATH`.
4. Сохраните прежний `SESSION_SECRET`/файл сессий — иначе пользователи потеряют доступ к своим анонимным кабинетам.
5. Запустите `npm start` (или `START_WINDOWS.cmd`). Миграция добавит таблицы для командных ссылок, заметок, документов, доказательств и журнала. Она не обнуляет прежние ветви.
6. Запустите `npm test`, `npm run ops -- doctor`, `npm run ops -- release-preflight`. Проверьте старую ветвь через ту же cookie-сессию.
7. Для отката остановите процесс и восстановите **всю старую папку данных** из копии, затем предыдущие исходники v2.8.0. Старой версии не гарантирована работа с файлом SQLite после новых операций v3.3.0.

### Что было фактически проверено

В тесте настоящая версия v2.8.0 создала анонимную сессию и дочернюю ветвь. Затем новая версия открыла **тот же файл SQLite**. Идентификаторы сессии и ветви, родитель и поколение сохранились; новые таблицы появились; `PRAGMA integrity_check` вернул `ok`, а `PRAGMA foreign_key_check` — ноль нарушений. Это ограниченная интеграционная проверка на тестовых данных, не проверка всех возможных старых production-баз.
