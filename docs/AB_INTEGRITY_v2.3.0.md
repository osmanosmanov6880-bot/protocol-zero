# Проверка достоверности A/B-экспериментов v2.3.0

`GET /api/experiments/{EXP-ID}/integrity` защищён сессией владельца одобренного бизнес-брифа. Ответ — JSON-отчёт с `arms.A`, `arms.B`, `balance`, `flags`, `decision`, `interpretation`. На экране `/lab/{BRF-ID}` доступна кнопка «Проверка данных» и экспорт JSON.

- `assignments` — количество уникальных стабильных псевдонимных ключей пользователей, назначенных live-партнёром.
- `impressions` — количество ключей с хотя бы одним подписанным показом. Не равно всем рекламным impressions биллинга.
- `goals` — количество ключей с хотя бы одним подписанным целевым событием **после** показа. Партнёр не может повторно увеличить число целей одного пользователя.
- `goalRate` — отношение целей к зарегистрированным показам, 95%-интервал Wilson. Интервал отражает только счётную неопределённость; не подтверждает корректную рандомизацию, определение конверсии или платёж.
- SRM: при сумме назначений ≥100 проверяется разделение 50/50 по хи-квадрат с 1 степенью свободы. Значение более 10,8276 означает серьёзный сигнал потенциальной ошибки интеграции/назначения. Это диагностический порог, а не тест эффективности.
- Флаг `EXPOSURE_IMBALANCE` при разнице долей показов >15 п.п. среди назначений, если в каждой группе >30 назначений.
- `descriptiveDifferencePercentagePoints` появляется только при ≥50 показах в каждой группе; показатель намеренно не называется uplift или победой.

Настоящее подтверждение продаж потребует интеграции с реальной рекламной платформой и независимой платёжной/CRM-сверкой. Рекомендации по выборке, предварительной регистрации плана, продолжительности и фильтрации трафика остаются отдельным исследованием.
