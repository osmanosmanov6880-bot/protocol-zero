# PROTOCOL ZERO / THE INHERITANCE ENGINE 1.3.0

**Дата сборки:** 22 октября 2026 года. **Тип:** локальный функциональный релиз, не публикация в интернете.

## Реализовано

1. **Business Intake:** новый адаптивный экран «Для бизнеса» и API для приватного предложения рекламной кампании. Встроены проверка прав/согласия на публикацию, опциональный контактный email с отдельным согласием, серверная валидация и квоты.
2. **Ручная публикация:** CLI-очередь, просмотр заявления, одобрение и отказ с аудитом; одобрение создаёт настоящий новый публичный `BR-*` корень в SQLite.
3. **Защита публикации:** оператор может скрыть весь корень, его потомков и связанные карточки/инвайты/хэнд-оффы и позднее восстановить.
4. **Кабинет бренда:** заявитель видит статус, по одобренной кампании просматривает и экспортирует публичные продолжения других участников. Чужие частные материалы недоступны.
5. **Конверсионный SDK:** серверный `sdk/node-partner.js` для подписи запросов HMAC v2 (resolve/confirm). Отдельная демоплатформа теперь вызывает тот же SDK, что предлагается настоящим Node.js-продуктам.
6. **UI и мобильная версия:** исправлена мобильная навигация, новые рабочие формы и просмотр историй, раздельная маркировка демобрифов и заявок.
7. **Совместимость:** все существующие 19 тестов из 1.2.0 продолжают выполняться; добавлены тесты заявок, статусов, безопасности, удаления, ручной публикации и доступа к вариантам.

## Проверено

- `npm run check` (синтаксис всей серверной, клиентской и SDK части).
- `npm test` (29 из 29 проверок, включая реальный HTTP второго sandbox-сервера).
- Chromium со встроенным API-мостом: desktop 1440×900 и mobile 390×844, форма → приватная заявка → операторская публикация → мутация чужого пользователя → просмотр публичных вариантов; ошибки JS отсутствуют, горизонтального overflow нет.
- Прямая Chromium-навигация в локальные адреса заблокирована административными правилами тестовой среды, поэтому визуальный E2E проверялся в изолированном браузере с реальными API-ответами, а сетевые HTTP-тесты — отдельно. Это **не** production-тест.
- Перенос базы и повторный запуск после миграции из предыдущих форматов покрываются тестами и инструкцией, но перед боевым обновлением необходимо сохранить бэкап.

## Честные ограничения

- По-прежнему нет фактического подключения к семи рекламным платформам — неизвестны их подтверждённые URL, API и действия сохранения.
- Нет покупок, платёжного провайдера, выставления счетов, внешней публикации и доказательства спроса. Невозможно считать демоконверсии настоящими продажами.
- Нет независимой проверки заявленных рекламодателями фактов или прав на бренд; оператор обязан проверять это вручную.
- Нет учётных записей компаний, централизованного провайдера email, автоуведомлений или профессионального B2B-договора.
- Применимы дополнительные правовые, операционные, антифрод- и security требования до массового публичного запуска.

Рекомендуемый следующий инженерный этап: получить код или спецификации первой настоящей рекламной платформы, внедрить SDK в её backend и проверить факт сохранённого рекламного материала на двух независимых пользовательских сессиях.
