# PROTOCOL ZERO — пять выполненных волн v1.8.0

## Базовая версия

Проект расширяет v1.3.0. Неизменяемая родословная, приглашения, частные мастерские, приём брифов компаний, ручное одобрение, модерирование, экспорт, две локальные площадки и HMAC Conversion Bridge сохраняются. Обновление базы аддитивное; заменять архив на работающем сервере нельзя.

## WAVE 1 — Creative Safety / Проверка формулировок

- Детерминированный анализ HOOK / CTA / контекста кампании: числовые обещания, гарантии, срочность, ссылки и контакты.
- API: `POST /api/preflight` (проверка черновика), `GET /api/branches/:id/preflight` (видимая ветвь).
- Контакты в публичных пользовательских мутациях блокируются; остальные флаги показываются как причины ручной проверки.
- Анализ **не** является юридическим заключением, автоматическим фактчекингом или оценкой эффективности. Правдивость продуктовых утверждений подтверждает рекламодатель.

## WAVE 2 — Curation / Редакционный выбор бизнеса

- Владелец опубликованного брифа может пометить видимый дочерний вариант как `candidate`, `shortlisted` или `discarded`, приложить приватную заметку до 700 символов.
- API: `GET/PUT /api/business-briefs/:id/reviews`. Изменение редакционного статуса не переписывает публичную родословную.
- Статусы и заметки доступны только владельцу того же анонимного сеанса, исключаются из публичного API, а скрытые модератором ветви не попадают в список отбора.
- `Результаты людей` дополнены инструментами отбора и выгрузки.

## WAVE 3 — Experiment Lab / Реальные A/B-планы

- У владельца кампании есть отдельная страница `/lab/:briefId`: выбрать **два** разных опубликованных варианта, основную метрику (`lead`, `signup`, `purchase`), описание гипотезы.
- Снимки рекламных вариантов сохраняются неизменяемыми; максимум 8 планов для одного брифа.
- Пока нет живой интеграции, эксперимент имеет статус `draft` и не собирает придуманные события.
- После активации с конфигурацией `mode:"live"` backend партнёра использует подписанные запросы для назначения A/B и регистрации показа / целевого события.
- Назначение участника закрепляется; показы и цели учитываются один раз; goal без предыдущего показа отклоняется; event ID защищены от повторной обработки.
- Показатели описательные. Проверку рандомизации, аудит трафика, статистическую значимость, защиту от ботов и достоверность цели должен обеспечить оператор реального сайта до вывода о выигрыше.

## WAVE 4 — Insight Studio / Измерение творческого участия

- Страница `/insights/:briefId` показывает видимые мутации, активные браузерные сессии, приглашения и их завершения, распределение изменяемых генов, недельную динамику и редакционный отбор.
- Анонимная браузерная сессия — не уникальный человек. Показатель первых наблюдаемых приглашённых авторов **не** объявляется причинным viral K.
- Частные заметки, непринятые заявки и скрытые модератором потомки отсутствуют в агрегатах.
- Подписанные события A/B отдельно от игровых событий и не подменяют продажи.

## WAVE 5 — Operations / Надёжный выпуск

- `/api/ready` проверяет SQLite и позволяет readiness-monitoring; Docker healthcheck проверяет его.
- Сессия хранит `last_seen_at`. Миграция старой базы не удаляет историю и корректно переносит дату последней активности.
- Операторский `npm run ops -- prune` по умолчанию показывает только кандидатов на очистку; реальное удаление требует `--execute --backup-confirmed` и предварительного резервного копирования.
- `npm run ops -- experiments` показывает оператору состояния A/B-планов без открытой веб-админки.
- CI под Node.js 22: статическая проверка JavaScript, автоматические тесты, smoke-тест запуска сервера.
- Сохранены CSP, разграничение доступа, HMAC-подписи и отсутствие секретов в браузере.

## Ограничения и эксплуатационные требования

**Пять волн реализованы как работоспособная функциональность локального веб-приложения.** Это не пять подключённых компаний и не пять подтверждённых бизнес-результатов. Внешние семь сайтов не подключены, платежи не проводились, коммерческий эффект не установлен, production-деплой не выполнялся. Публичный запуск требует TLS, юридической и privacy-проверки, настройки реального партнёра, резервных копий, мониторинга, защиты от массовых злоупотреблений и нагрузки.

Проверить локально: `npm run check`, `npm test`, `npm run smoke`, `npm run verify:release`. Сценарий для бизнеса: `/submit` -> ручное одобрение -> другая сессия создаёт мутацию -> владелец видит `Результаты людей`, `/lab/BRF-...` и `/insights/BRF-...`.
