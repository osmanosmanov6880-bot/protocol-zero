# Первый коммерческий спрос — конвейер пилотных запросов

Клиент сначала подаёт рекламный бриф, оператор его публикует. Затем в «Для бизнеса» → «Платный пилот» владелец заявки отправляет **бесплатный запрос на обсуждение работ**. Указание бюджета не инициирует оплату.

Состояния:

```text
requested --> reviewing --> proposal_sent --> accepted (только владелец брифа)
      |           |                |---> declined (владелец / оператор)
      |           |---> declined
      |---> withdrawn (владелец)
      |---> proposal_sent
```

Операторский CLI:

```bash
npm run ops -- pilots
npm run ops -- pilot-view PIL-ID
npm run ops -- pilot-review PIL-ID "Проверили задачу и допустимый бюджет"
npm run ops -- pilot-offer PIL-ID 75000 "Предварительная цена и сроки зафиксированы" "Сделаем два рекламных варианта, согласуем гипотезу и оформим отчёт; результат не гарантируется."
npm run ops -- pilot-decline PIL-ID "Недостаточно данных для честной проверки"
```

`75000` в CLI = **750,00 EUR**, поскольку передаются **евроценты**. В `proposal` нельзя передавать HTML и управляющие символы. Для реального выставления счетов потребуется отдельно подключить платёжный сервис, налоги, юридическое лицо и подтверждение поступлений. Сейчас отсутствуют счет, платёж, выручка, независимое подтверждение личности, электронная подпись.

Отвечать на запрос можно через private operator CLI/в том же анонимном браузере. Контактный email, если был передан при первоначальном брифе, следует использовать только для ответа по заявке с указанным отдельным согласием, без рекламной рассылки.
