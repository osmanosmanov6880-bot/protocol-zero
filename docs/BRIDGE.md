# PROTOCOL ZERO / CONVERSION BRIDGE v2

**Что внедрено:** подлинная цепочка из двух Node.js-приложений (портал и тестовый внешний редактор), не просто клики по URL. **Что пока не внедрено:** подключения к семи работающим локально рекламным сайтам, платёжная система и доказательство продаж.

## Один запуск без настроек

На Windows: `START_DEMO_WINDOWS.cmd`. На macOS/Linux: `./START_DEMO_MAC_LINUX.sh`. Или `npm run demo`.

Откройте `http://127.0.0.1:8787` → измените любой из трёх демобрифов → «Передать в продукт» → выберите тестовую мастерскую → ознакомьтесь с составом данных → подтвердите → откройте партнёра → «Сохранить демонстрационный рекламный макет» → вернитесь на вкладку «Рекламный мост» (если страница осталась на партнёре, откройте `http://127.0.0.1:8787/bridge`).

Результат:
- портал хранит `handoffs` с уникальным случайным 32-символьным идентификатором;
- другой сервер запрашивает бриф по подписанному API;
- деморедактор сохраняет свой `demo_artifacts` в **отдельной SQLite-базе**;
- сервер партнёра подписывает callback и отправляет в портал;
- портал хранит `partner_receipts`, учитывает событие только в `sandboxActions`, **не** в `verifiedActions` и **не** как реальные продажи.

Демо-макет живёт в `data/demo-partner.sqlite`. Его нельзя выдавать за рекламный материал одной из семи реальных компаний.

## Семь реальных рекламных сайтов: интеграционный контракт

У нас **нет подтверждённых URL, названий и API** семи продуктов. Их невозможно подключить корректно, пока оператор не подтвердит возможности как минимум одного. Перед подключением заполнить для каждого:

| Вопрос | Что записать |
|---|---|
| Домен / локальный путь | Настоящий доступный с сайта PROTOCOL ZERO адрес |
| Действие, за которое есть ценность | Например, фактическое сохранение рекламного макета — **только если продукт это умеет** |
| Где принимает ссылку | GET landing с параметром `pz_handoff` |
| Есть ли серверный код | Нужен для HTTPS запросов и подписи HMAC |
| Кто владелец пользовательских данных | Определить для privacy notice и соглашений |
| Как вернуть доказательство | `event_id`, `handoff_id`, `action_type`, `partner_object_id` |
| Как пользователь возвращается | Ссылка на PROTOCOL ZERO; **не** обещать уведомления, пока не подключены |

Заполните `config/platforms.example.json`, сохраните рабочую копию как `config/platforms.live.json` (в приватной инфраструктуре, не в публичный архив), выставьте `PZ_PLATFORMS_FILE` и для каждого `secretEnv` установите случайный секрет >=32 символов. Максимум семь платформ, у каждого `key` уникален. В production HTTP и `mode:"sandbox"` отклоняются при старте.

**Важно:** реестр с URL не означает, что внешний сайт интегрирован. Только собственный server-side код сайта способен принять бриф и подтвердить действие. Для любых `capabilities` используйте фактические возможности; если API нет, пока оставляйте только экспорт брифа и ручной переход без обещания подтверждения.

## API-поток

1. Автор **своей** публичной ветви нажимает «Передать в продукт». Он явно соглашается со списком передаваемых полей. Для приватной рабочей копии есть отдельная опция, передающая также его заметки.
2. Браузер выполняет `POST /api/handoffs` с JSON:

```json
{"branchId":"7F-001-ИДЕНТИФИКАТОР","platformKey":"real_product_one","source":"public"}
```

Ответ 201: `{"id":"...", "launchPath":"/out/ID", "platform":{"key":"...","name":"...","mode":"live"}, ...}`. Секрет в ответе отсутствует.

3. Браузер открывает `GET /out/ID`. Сервер проверяет исходную анонимную сессию владельца, состояние модерации, отзыв, срок действия и платформу из конфигурации. Ответ `302` на разрешённый URL с параметром `pz_handoff=ID` и безопасными UTM (`utm_source=protocol_zero`, `utm_medium=interactive`, `utm_campaign=inheritance_7f`). **Тексты и заметки не помещаются в URL.**
4. **Backend платформы** выполняет `POST /api/integrations/v2/resolve`:

```json
{"handoff_id":"ID"}
```

Только после реально открытого перехода, с HMAC-заголовками (ниже). Ответ содержит `brief`, `handoffId`, `source`, `mode`, `expiresAt`. Бриф содержит заявленные поля: происхождение, аудиторию, задачу, визуальные ограничения, доказательства и творческий блок. При `source:"workspace"` ещё и сохранённые заметки автора.
5. На **реальном сервере продукта** пользователь создаёт и сохраняет рекламный результат. Только после успешного сохранения его backend выполняет `POST /api/integrations/v2/confirm`:

```json
{
  "event_id":"your-provider-event-000001",
  "handoff_id":"ID",
  "action_type":"artifact_created",
  "partner_object_id":"your-saved-object-id-123"
}
```

Второй разрешённый тип `campaign_saved`. Не отправляйте событие на открытие лендинга, регистрацию или самоотчёт. `event_id` уникален внутри одного партнёра, повтор точно того же события идемпотентен; конфликтующие повторы получают HTTP 409.

## Подпись обоих запросов партнёра

Заголовки:

```http
X-PZ-Platform: real_product_one
X-PZ-Timestamp: 1790000000
X-PZ-Signature: sha256=<64 lowercase hex>
Content-Type: application/json
```

`X-PZ-Timestamp` должен быть **реальным временем запроса** в секундах Unix, а не примером выше. Время допускается ±300 секунд. Подпись:

```js
const crypto = require('node:crypto');
const raw = JSON.stringify(payload);
const timestamp = String(Math.floor(Date.now()/1000));
const signature = 'sha256=' + crypto.createHmac('sha256', process.env.MY_SECRET)
  .update(timestamp + '.' + raw).digest('hex');
```

Подпишите **именно байты raw JSON**, затем отправьте эти же байты в body. Не создавайте секрет в браузере и не публикуйте его в исходниках. Партнёрский запрос нельзя послать из frontend напрямую. Полный автономный пример см. `examples/partner-sandbox.js`.

## Авторство, безопасность, приватность

- Любую передачу создаёт только автор ветви; чужой рабочий черновик нельзя прочесть.
- Передача работает только после перехода владельца. Backend чужого партнёра не может её получить.
- Токен `pz_handoff` не содержит email, данные сессии, секреты или рекламный текст; это случайный идентификатор ссылки, поэтому его всё равно следует считать конфиденциальным.
- Отмена через `POST /api/handoffs/ID/revoke` не удаляет уже импортированный партнёром бриф — это нужно обеспечить отдельно через договорённости об удалении данных.
- Срок действия передачи — 30 дней. Скрытые модератором ветви недоступны в bridge.
- При удалении анонимной сессии передача и её серверный снимок удаляются в приложении PROTOCOL ZERO. Ранее полученный партнёром материал **остаётся вне нашей области контроля**.
- Событие `live` означает только подписанное подтверждение **настроенного** сервера платформы, но не рост продаж и не доказательство рекламной эффективности.
- Нужны HTTPS, секреты с ротацией, договоры обработки данных, ограничение входящего трафика и проверка легитимности партнёра до production.

## Операторские команды

```bash
npm run ops -- report
npm run ops -- funnel
npm run ops -- handoffs
npm run ops -- funnel-csv /secure/report.csv
npm run backup
```

CSV создаётся с запретом перезаписи, без персональных данных. Воронка считает уникальные **анонимные браузерные сеансы**, а не уникальных людей, не cohort retention, и отделяет события frontend от подписанного API.
